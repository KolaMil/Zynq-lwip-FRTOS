# Zynq-7000_lwip_FRTOS

Проект представляет собой PS-часть для системного модуля (SOM) **PZ7030-SOM-676** на базе микросхемы XC7Z030
В файле cmd.h представлены команды, на которые будет реагировать модуль.
На данный момент проект в ожидании реализации FPGA-части(PL) для возможности реализации обмена данными между PL и PS частями. Так же заложено начало межядерного взаимодествия.
UDP-передача работает **исключительно после** команды от сервера. Настроен режим мониторинга и переподключения к серверу по TCP-протоколу в случае разрыва соединения.
Реализована непрерывная отправка сообщений по UDP. **Скорость передачи - до 50 мкс**

По файлам:
cpu1_init.c и cpu1_init.h - функцианирование второго ядра в параллели с основным
main.c main.h - старт программы, создание всех подзадач, запуск планировщика, параметры для тредов
IntQueueTimer.c IntQueueTimer.h - описание таймеров, 
lwip.c lwip.h - всё что связано с ethernet, поднастройки, инициализации, контроль состояний
tcp_stack.c tcp_stack.h - пока тут описание и работа монитора состояний tcp-клиента. Планируется перенести больше функций для tcp
udp_stack.c udp_stack.h - описание и функционал отправки сообщений по UDP-протоколу с помощью отдельной структуры
platform.c platform.h - инициализация железной части, необходимой для работы PS части

# По функционалу:
## maic.c:

main() - старт программы
network_init_task() - полная инициализация lwip части, создание задач связанных ethernet
udp_send_task() - отправка пакета по UDP
tcp_parse_task() - парсинг пришедшего пакета
vStatsTask() - сбор статистики по времени отправки UDP, проверка зависших соединений TCP
vTcpStatTask() - мониторинг и вывод ситуации по TCP-клиенту
x1emacif_input_thread() - запуск таймеров, следящих за low layout ethernet на xilinx

## lwip.c

lwip_network_setup() - установка в low layout настроек для ethernet
udp_connection() - запись информации о том, куда будем посылать, создание структуры для отправки (sender)
udp_package_send() - обертка для отправки сообщений
tcp_connection_cl() - настройка конфигурации для TCP подключения, создание структуры для мониторинга TCP(monitor), попытка фактического подключения
need_reconnect() - проверка необходимости рестартануть TCP подключения
reconnection_tcp() - сам реконнект, связан с необходимостью полностью корректно удалить данные о TCP и снова создать
tcp_client_close() - мягкое отключение от существующего соединения
client_connected() - **callback** функция, срабатывающая при успешном подключении
get_tetrada() - взятие тетрады из команды, по ней идет парсинг
parse_msg() - функция парса сообщения
recv_callback() - **callback** функция, срабатывающая при получении любого пакета в TCP

destroy_monitor() - удаление структуры согласно правилам, чтобы не допустить утечку

## udp_stack.c

add_sender() - конструктор для структуры отправщика
send_udp_data() - функция отправки данных по UDP
destroy_sender() - корректное удаление структуры
